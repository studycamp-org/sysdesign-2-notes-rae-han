# 시나리오 카드

각 시나리오는 교재 기준안(DAU 10억 / 1인 주당 35분 경로 안내 / 15초 묶음 위치 전송 / 미리 만든 지도 타일 + CDN / 계층적 경로 안내 타일 / 웹소켓으로 경로 변경 알림)과
일부러 다른 제약을 하나 이상 넣어서, 같은 질문이라도 다른 선택이 정당화되도록 만들었다.

목록을 보여줄 때는 `한 줄 요약`만 보여준다. 고른 뒤에 카드 전체를 보여준다.

계산 공통 가정(카드에 따로 없으면): 하루 ≈ 10⁵초, 이동 속도 30km/h, 지도 타일 1장 = 200m × 200m · 256 × 256 픽셀 · 100KB → 경로 안내 중 지도 데이터 **분당 1.25MB**(래스터 기준), 피크 = 평균 × 5.

---

## S1. 길동무 — 국내 자동차 내비  (입문 / 교재와 가장 비슷함)

**한 줄 요약**: 한국 전용 자동차 내비. 출퇴근 사용이 많고, 규모는 교재보다 훨씬 작다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 (면적 약 10만 km²) |
| DAU | 2,000만 |
| 경로 안내 사용 | 1인 **주당 70분** (출퇴근) |
| 위치 전송 | 교재처럼 클라이언트가 모아서 15초마다 |
| 이동 수단 | 자동차만 |
| 정확도 | 잘못된 경로 안내는 치명적. 출퇴근 시간 ETA 오차 ±3분 이내가 목표 |
| 지도 | 국내 도로만. 고층 건물 밀집 지역(강남, 여의도)은 확대해서 보는 일이 많다 |

**설계 포인트**: 교재 구조를 축소해서 그대로 쓸 수 있는지, 국내 한정이면 무엇을 더 단순하게 갈 수 있는지.

**돌발 상황**: "금요일 오후 6시, 경부고속도로 서울 방향에서 대형 사고로 전 차로가 1시간 통제됩니다. 이 구간을 지나는 경로로 안내 중인 사용자가 30만 명입니다. 누구에게, 얼마나 빨리, 어떻게 새 경로를 알리나요?"

---

## S2. 월드맵 — 전 세계 지도·길찾기  (교재 수치 그대로)

**한 줄 요약**: 구글 맵과 같은 규모. 전 세계 지도, 자동차·도보·대중교통 길찾기.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 전 세계 |
| DAU | 10억 |
| 경로 안내 사용 | 1인 **주당 35분** |
| 위치 전송 | 클라이언트가 모아서 15초마다 |
| 이동 수단 | 자동차, 도보, 자전거, 대중교통 |
| 지도 | 확대 수준 0~21. 사람이 살지 않는 지역(바다·사막)이 표면의 대부분 |
| 데이터 사용량 | 신흥국 사용자가 많아 모바일 데이터 요금에 민감하다 |

**설계 포인트**: 지도 타일 저장(수십 PB)과 CDN 트래픽, 대륙을 넘는 장거리 경로가 동시에 문제다.

**돌발 상황**: "도쿄 일대에 규모 7 지진이 나서 도로 수백 곳이 동시에 끊겼고, 대피하려는 사용자 2,000만 명이 10분 안에 경로 안내를 동시에 요청합니다. 경로 안내 타일은 '도로 정상' 상태로 만들어져 있습니다. 무엇이 먼저 무너지고 어떻게 대응하나요?"

---

## S3. 번개배달 — 배달 라이더 내비 + 고객 실시간 추적  (짧은 주기 / 경유지 변형)

**한 줄 요약**: 라이더 전용 내비. 5초마다 위치를 보내고, 고객 앱에 라이더 위치를 실시간으로 보여준다. 한 번에 여러 집을 들른다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 수도권 |
| 라이더 DAU | 20만 (하루 평균 **8시간** 운행) |
| 위치 전송 | **5초마다, 묶지 않음** (고객 추적 화면과 배차에 바로 쓰임) |
| 피크 | 점심·저녁 시간 평균의 **4배** |
| 이동 수단 | 오토바이 (골목길, 아파트 단지 내부 도로가 중요) |
| 경로 | 한 번에 **최대 5곳**을 들르는 다중 경유지. 들르는 순서 최적화 필요 |
| 고객 추적 | 주문 고객이 라이더 위치를 지도에서 실시간으로 본다 (라이더 1명당 고객 평균 3명) |

**설계 포인트**: 교재의 "15초 묶음 전송, 경유지 없음, 사용자 본인에게만 알림" 가정이 깨진다. 위치가 본인 말고 고객에게도 흘러가야 한다.

**돌발 상황**: "폭우로 주문이 평소의 3배가 되고, 라이더 앱이 경로 재계산 요청을 1분마다 보내기 시작했습니다. 동시에 침수로 도로 50곳이 통제됐습니다. 경로 서비스와 알림 경로 중 무엇이 먼저 병목이 되나요?"

## S4. 산길 — 등산·자전거 오프라인 지도  (낮은 데이터 / 오프라인 변형)

**한 줄 요약**: 산과 자전거길 지도. 통신이 끊기는 곳이 많아 지도를 미리 내려받아 쓴다. 교통 정보는 거의 의미 없다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 산지·자전거길 |
| DAU | 100만 (주말 피크 **평일의 4배**) |
| 사용 시간 | 활동하는 날 평균 **3시간** |
| 통신 | 산간 구간 **30% 이상 통신 불가**. 활동 중 위치는 기기에 쌓았다가 통신될 때 올림 |
| 지도 | 등산로·임도·자전거길 포함, 등고선 필요. **국립공원 1곳(약 500km²) 오프라인 다운로드** 기능 |
| 경로 | 도로 교통 대신 경사·노면·소요 시간(오르막 속도 저하)이 경로 비용 |
| 데이터 보호 | 활동 기록(GPS 트랙)은 사용자 소유, 영구 보관·내보내기 지원 |

**설계 포인트**: "서버가 항상 연결돼 있고 타일은 그때그때 CDN에서 받는다"는 교재 가정이 깨진다. 지도와 경로 탐색 일부가 단말로 내려온다.

**돌발 상황**: "가을 단풍 주말, 설악산 한 곳에 5만 명이 몰리고 그중 1만 명이 출발 직전 주차장(통신 약함)에서 국립공원 지도를 동시에 내려받으려 합니다. 동시에 낙석으로 등산로 2곳이 폐쇄됐는데, 이미 지도를 내려받은 사람들은 이 사실을 모릅니다. 어떻게 하나요?"

## 직접 만들기

다음 항목을 사용자와 함께 채워서 카드를 만든다. 빈 칸은 진행자가 그럴듯한 값을 제안하고 동의를 받는다.

- 서비스 성격(자동차 내비 / 도보·대중교통 / 배달·물류 / 아웃도어) / 지역 범위 / DAU
- 1인 경로 안내 사용 시간 / 위치 전송 주기와 묶음 여부 / 피크 배수
- 이동 수단과 경로 비용 기준(시간, 거리, 통행료, 경사 등) / 경유지 유무
- 통신 환경(항상 연결 / 자주 끊김) / 데이터 사용량 민감도
- 돌발 상황 1개 (진행자가 만들되, 시나리오의 가장 약한 가정을 깨는 것으로)

## 랜덤

S1~S4 중 하나를 무작위로 고른다. 입문자라면 S1을 권한다.
