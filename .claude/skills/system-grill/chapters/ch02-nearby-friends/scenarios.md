# 시나리오 카드

각 시나리오는 교재 기준안(친구 최대 5,000명 / 30초 갱신 / 일부 유실 허용 / 사용자별 펍/섭 채널)과
일부러 다른 제약을 하나 이상 넣어서, 같은 질문이라도 다른 선택이 정당화되도록 만들었다.

목록을 보여줄 때는 `한 줄 요약`만 보여준다. 고른 뒤에 카드 전체를 보여준다.

---

## S1. 동네친구 — 국내 친구 위치 공유 앱  (입문 / 교재와 가장 비슷함)

**한 줄 요약**: 한국 전용 친구 위치 공유. 30초 갱신, 약간의 유실과 지연은 괜찮다. 규모는 교재의 1/5.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 2,000만 |
| 동시 접속 | DAU의 10% |
| 평균 친구 수 | 150명 (상한 1,000명), 그중 반경 안 활성 친구는 약 10% |
| 위치 갱신 주기 | 30초 |
| 검색 반경 | 5km |
| 유실·지연 | 몇 번의 갱신 유실은 괜찮다. 친구 화면에는 "마지막 갱신 시각"을 함께 보여준다 |
| 데이터 보호 | 위치 공유는 opt-in. 위치 이력은 ML용으로 30일만 보관 |

**설계 포인트**: 교재 구조를 축소해서 그대로 쓸 수 있는지, 아니면 이 규모에서는 더 단순하게 갈 수 있는지.

**돌발 상황**: "12월 31일 밤 11시 50분, 동시 접속이 평소의 3배로 뛰고 그중 40%가 서울 도심 몇 곳에 몰립니다. 같은 시각 레디스 펍/섭 서버 한 대가 죽었습니다. 무엇이 먼저 무너지고 어떻게 복구하나요?"

---

## S2. 글로벌 프렌즈 — 전 세계 친구 위치 공유  (교재 수치 그대로)

**한 줄 요약**: 전 세계 대상. 교재 수치와 같은 규모. 지역별 개인정보 규제가 다르다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 전 세계 |
| DAU | 1억 |
| 동시 접속 | DAU의 10% |
| 평균 친구 수 | 400명 (상한 5,000명), 그중 반경 안 활성 친구는 약 10% |
| 위치 갱신 주기 | 30초 |
| 검색 반경 | 5마일(약 8km) |
| 유실·지연 | 일부 유실 허용. 몇 초 정도의 지연은 괜찮다 |
| 데이터 보호 | EU GDPR 등 지역별 법규. 일부 국가는 위치 데이터를 국외로 반출할 수 없다 |

**설계 포인트**: 친구가 다른 대륙에 있을 수 있다. 친구 관계는 국경을 넘는데 데이터는 국경을 못 넘는다.

**돌발 상황**: "사용자가 6개월 만에 2배가 되어 펍/섭 클러스터를 지금의 2배로 늘려야 합니다. 해시 링에 서버를 추가하는 순간 무슨 일이 생기나요? 언제, 어떻게 늘리겠습니까?"

---

## S3. 같이달려 — 러닝·라이딩 크루 실시간 위치  (짧은 주기 / 그룹 변형)

**한 줄 요약**: 친구가 아니라 크루(그룹) 단위 공유. 5초마다 갱신하고, 같이 달리니 대부분 반경 안이다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 200만 |
| 동시 접속 | 평소 DAU의 5%, **주말 아침 피크 20%** |
| 공유 대상 | 크루 단위. 평균 크루 20명, 상한 100명. 함께 달리는 중이라 **거의 전원이 반경 안** |
| 위치 갱신 주기 | **5초** (자전거 30km/h면 30초에 250m를 이동) |
| 검색 반경 | 크루 전체 (반경 제한 없음, 같은 활동 세션에 참여한 사람) |
| 유실·지연 | 지도에서 위치가 튀면 안 된다. 연속 2회 이상 유실은 사용자 불만 |
| 데이터 보호 | 활동 기록(경로)은 사용자 소유. 영구 보관하고 내보내기를 지원 |

**설계 포인트**: 교재의 "30초 갱신, 유실 허용, 위치 이력은 부가 기능" 가정이 깨진다. 이력이 핵심 기능이다.

**돌발 상황**: "서울 마라톤 공식 파트너가 되어, 참가자 3만 명이 '대회 크루' 하나에 들어갑니다. 크루 상한 100명 가정이 깨졌습니다. 채널 하나에 구독자 3만 명이면 어떻게 되나요?"

---

## S4. 지금여기 — 주변 임의 사용자 보기  (지오해시 채널 변형)

**한 줄 요약**: 친구가 아니라 반경 안의 **모르는 사용자**를 보여준다. 친구 그래프가 없다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 500만 |
| 동시 접속 | DAU의 10% |
| 공유 대상 | 위치 공개를 켠 반경 안 임의 사용자. 화면에는 최대 50명만 표시 |
| 위치 갱신 주기 | 30초 |
| 검색 반경 | 1km |
| 유실·지연 | 유실 허용. 정확한 위치 대신 **약 100m 단위로 흐린 위치**만 공개 |
| 데이터 보호 | 위치 이력 저장 금지. 차단한 사용자에게는 노출되면 안 된다 |

**설계 포인트**: 사용자별 채널(친구 구독)이 성립하지 않는다. 공간 단위 채널, 인접 격자 구독, 밀집 지역 처리가 쟁점이다.

**돌발 상황**: "잠실 주경기장 콘서트에 5만 명이 모였고 그중 2만 명이 위치 공개를 켰습니다. 한 격자 채널에 수만 명이 발행·구독합니다. 어떻게 하나요?"

---

## 직접 만들기

다음 항목을 사용자와 함께 채워서 카드를 만든다. 빈 칸은 진행자가 그럴듯한 값을 제안하고 동의를 받는다.

- 서비스 성격(친구 / 그룹 / 임의 사용자) / 지역 범위 / DAU / 동시 접속 비율
- 1인당 평균 친구(또는 노출 대상) 수와 그중 반경 안 활성 비율
- 위치 갱신 주기 / 검색 반경 / 유실·지연 허용 정도 / 위치 이력 보관 정책
- 돌발 상황 1개 (진행자가 만들되, 시나리오의 가장 약한 가정을 깨는 것으로)

## 랜덤

S1~S4 중 하나를 무작위로 고른다. 입문자라면 S1을 권한다.
