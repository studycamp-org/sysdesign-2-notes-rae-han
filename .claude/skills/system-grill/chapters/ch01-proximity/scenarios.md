# 시나리오 카드

각 시나리오는 교재 기준안(전 세계 / 지오해시 / 다음날 반영)과 일부러 다른 제약을 하나 이상 넣어서,
같은 질문이라도 다른 선택이 정당화되도록 만들었다.

목록을 보여줄 때는 `한 줄 요약`만 보여준다. 고른 뒤에 카드 전체를 보여준다.

---

## S1. 동네맛집 — 국내 맛집 검색 앱  (입문 / 교재와 가장 비슷함)

**한 줄 요약**: 한국 전용 맛집 검색. 서울 도심은 밀집, 지방은 희소. 정보 변경은 다음날 반영이면 된다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 1,000만 |
| 1인당 하루 검색 | 10회 |
| 등록 사업장 수 | 300만 |
| 피크 | 점심(11:30~13:00), 저녁(18:00~20:00)에 평균의 약 5배 |
| 검색 반경 | 앱에서 500m / 1km / 2km / 5km 중 선택 |
| 정보 변경 반영 | 사장님이 수정한 정보는 **다음날** 검색에 반영되면 된다 |
| 데이터 보호 | 개인정보보호법 준수, 사용자 위치 이력 보관에 대한 내부 정책 필요 |

**설계 포인트**: 강남역 반경 500m와 강원도 산간 반경 5km의 사업장 밀도가 극단적으로 다르다.

**돌발 상황**: "TV 맛집 프로그램 방영 직후 특정 동네 검색이 평소의 30배로 몰립니다. 그 지역 셀의 캐시와 DB는 버틸까요?"

---

## S2. 글로벌 트립 — 전 세계 여행자용 주변 장소 검색  (교재 수치 그대로)

**한 줄 요약**: 전 세계 대상. 교재 수치와 같은 규모. 국가별 개인정보 규제가 다르다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 전 세계 |
| DAU | 1억 |
| 1인당 하루 검색 | 5회 |
| 등록 사업장 수 | 2억 |
| 피크 | 지역마다 시간대가 달라 전 세계 합계는 비교적 평탄. 지역 단위로는 2~3배 |
| 검색 반경 | **사용자가 슬라이더로 자유롭게 지정**(100m~20km) |
| 정보 변경 반영 | 다음날 반영 허용 |
| 데이터 보호 | EU GDPR 등 **지역별 법규**. 일부 국가는 데이터를 국외로 반출할 수 없다 |

**설계 포인트**: 반경이 자유 입력이라 고정 정밀도 표가 그대로 맞지 않는다. 지역별 데이터 거주(data residency) 요구가 있다.

**돌발 상황**: "EU 규제 당국이 EU 사용자의 위치 검색 요청이 EU 밖 서버를 거치면 안 된다고 통보했습니다. 지금 배치 구조로 괜찮나요?"

## S3. 트럭맵 — 푸드트럭·팝업스토어 실시간 지도  (갱신이 잦은 변형)

**한 줄 요약**: 사업장(트럭)이 하루에 여러 번 위치를 옮긴다. 위치 변경은 1분 안에 검색에 반영되어야 한다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 300만 |
| 1인당 하루 검색 | 8회 |
| 등록 사업장 수 | 50만 (이 중 이동형 20만) |
| 위치 변경 빈도 | 이동형 사업장 1곳이 하루 평균 4회 위치 변경 |
| 피크 | 주말 축제·불꽃놀이 행사장 주변에 평소의 10배 |
| 검색 반경 | 300m / 1km / 3km |
| 정보 변경 반영 | **위치 변경은 1분 안에** 검색 결과에 반영. 메뉴·사진은 다음날이어도 된다 |
| 데이터 보호 | 사업장 위치는 공개 정보. 사용자 위치는 저장 금지 |

**설계 포인트**: 교재의 "다음날 반영" 가정이 깨진다. 쓰기 QPS와 색인 갱신 방식, 캐시 무효화가 핵심이다.

**돌발 상황**: "여의도 불꽃축제 당일, 트럭 2천 대가 한 시간 안에 같은 구역으로 이동해 왔고 사용자 50만 명이 그 구역을 검색합니다. 색인과 캐시가 어떻게 되나요?"

## S4. 우리동네 — 동네 인증 기반 지역 커뮤니티 마켓  (지오펜스 변형)

**한 줄 요약**: 반경 검색에 더해 "행정동 경계 안" 노출과 동네 이탈 감지가 필요하다.

| 항목 | 값 |
|---|---|
| 서비스 지역 | 대한민국 |
| DAU | 800만 |
| 1인당 하루 검색 | 12회 |
| 등록 사업장(가게·판매글 위치) 수 | 1,500만 |
| 검색 방식 | ① 반경 검색(1km / 3km / 6km) ② **내 행정동 + 인접 동** 범위 노출 |
| 추가 기능 | 사용자가 인증한 동네를 벗어나면 일부 기능 제한(동네 이탈 감지) |
| 정보 변경 반영 | 새 판매글은 **5분 안에** 노출 |
| 데이터 보호 | 인증 시점 위치만 저장. 상시 위치 추적 금지 |

**설계 포인트**: 원형 반경이 아니라 **불규칙한 경계**(행정동)를 다뤄야 한다. 지오펜스와 다단계 셀이 쟁점이다.

**돌발 상황**: "행정동 통폐합으로 경계가 바뀌었습니다. 내일부터 새 경계로 노출해야 합니다. 색인이나 데이터를 어떻게 바꾸나요?"

## 직접 만들기

다음 항목을 사용자와 함께 채워서 카드를 만든다. 빈 칸은 진행자가 그럴듯한 값을 제안하고 동의를 받는다.

- 서비스 성격 / 지역 범위 / DAU / 1인당 검색 횟수 / 사업장 수
- 피크 패턴 / 검색 반경 정책 / 정보 변경 반영 요구 / 데이터 보호 요구
- 돌발 상황 1개 (진행자가 만들되, 시나리오의 가장 약한 가정을 깨는 것으로)

## 랜덤
